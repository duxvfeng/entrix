# 代码质量（Code Quality）维度规范

编辑 `harness.yaml` 中的 `code_quality` 维度时使用本规范。

## 目的

保护代码本身的结构和可维护性。

## 典型信号

- lint
- typecheck
- clippy 或编译器警告
- 文件或函数预算
- 重复代码检查
- 结构异味扫描
- 复杂度限制

## 良好的 Metric 模式

- lint 和 typecheck 优先使用仓库脚本
- 如果仓库已经支持，对昂贵的静态检查使用感知 diff 的命令
- 只有确实应该阻塞合并的检查才设置硬门禁
- 不要将可选的工具链专属检查作为初始化 `fast` 硬门禁，除非它们可以在本地运行，
  或由已提交的仓库包装器负责准备环境

## 拆分指导

让 `code_quality` 专注于静态或源码本地的关注点。

不要将以下内容隐藏在此维度中：

- API parity 检查
- 运行时 telemetry probe
- E2E 流程
- 安全扫描器

## 叙述正文

使用 Markdown 正文说明：

- 代码质量失败在本仓库中的含义
- 设置特定预算或阈值的原因
- 已知的遗留热点或豁免
