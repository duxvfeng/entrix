# API 契约（API Contract）维度规范

编辑 `harness.yaml` 中的 `api_contract` 维度时使用本规范。

## 目的

保护客户端和集成所依赖的外部可见行为。

## 典型信号

- API parity 检查
- Schema 校验
- 端点行为矩阵
- 请求或响应兼容性测试
- 契约失败的负向路径覆盖

## 拆分指导

一个仓库保留以下内容是可以接受的：

- 一个用于可执行 API 测试的 evidence 文件
- 另一个用于更广泛兼容性或可演进性规则的 evidence 文件

重要的是，拆分必须明确且易于发现。

## 边界

当仓库存在明确的 API 保障时，不要把契约检查隐藏在通用测试分类中。
