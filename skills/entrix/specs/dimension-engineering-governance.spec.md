# 工程治理（Engineering Governance）维度规范

编辑 `harness.yaml` 中的 `engineering_governance` 维度时使用本规范。

## 目的

保护仓库整洁度、审查纪律和变更影响范围。

## 典型信号

- diff 大小或影响范围 probe
- 外部链接有效性
- TODO 或 FIXME 增长
- 脚本泛滥或预算执行
- 仓库策略符合性

## 边界

此维度关注安全的变更流程和仓库结构，而不是代码正确性本身。

如果检查实际关注以下内容，应将其移到其他维度：

- 代码语义或编译正确性
- 安全发现
- API 契约行为
- UI 渲染保真度

## 适用场景

- 帮助判断是否需要深入审查的检查
- 在高风险变更落地前发出警告或执行门禁的治理规则
